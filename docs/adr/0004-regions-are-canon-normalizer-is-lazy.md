# Regions are canon; the normalizer is a lazy chunk

Fill-drawn icons (Material Symbols, Heroicons solid, Phosphor, Remix, MDI, Bootstrap, MingCute…) can't fly on centerlines: their geometry is an outline, often a union of overlapping pieces with per-element fill rules, and a stroke icon drawn "filled" (Material outlined, Phosphor regular) looks like a stroke but isn't one. Any pair where one side is painted by fill now flies as **regions**: both endpoints are reduced to the visible surface (closed, non-overlapping contours, outers positive, holes negative, nonzero) and morph surface to surface. Stroke ↔ stroke keeps the centerline pipeline, byte-identical in behaviour.

We decided this is **canon, not an opt-in**: `<MorphIcon icon={open ? Close : Menu} />` must work for any two icons with no plugin, no registration call and no bundler integration (it has to work under webpack, Rollup, esbuild, Metro and plain `<script type="module">`, not just Vite). The capability is paid in two parts:

- **Static, in the driver (+2.0 KB gzip on dom and every binding):** only what must work before the chunk exists — the paint model (`paintOf`), the rest look of a fill icon (SSR included), paint writes on the element, and the lazy loader with its wait budget, fallback flight, idle prefetch and retry.
- **Lazy, a separate chunk (~5.4 KB gzip incremental, `morphicons/region`):** the normalizer (signed distance field + marching squares + corner recovery), the region planner and everything that can only run once they are around: region forms, samples and plans, cached by reference (the driver hooks `regionOf` / `regionPlan` / `regionPlanFrom`). It is loaded with `import()` the first time a morph involves a fill icon, or at mount when an icon is filled at rest. Stroke-only apps never download it.

## Considered Options

1. **Opt-in plugin / registration (`registerRegions()`), the ADR 0001 pattern.** Rejected for this capability. Unlike a foreign format, a fill icon is already a valid `IconInput` (an IconNode with `fill`), so silently flying it as centerlines would be a wrong result, not a missing feature. And forgetting the opt-in can't be detected at build time.
2. **Build-time normalization only (bundler plugin).** Rejected as the only path: it ties correctness to one toolchain. It stays available as an optimization, since `toRegion` is pure and its output (`data-region`) skips normalization at runtime.
3. **Everything static.** Rejected: +5.4 KB on every page for a capability many apps never use.
4. **Static driver half + lazy normalizer (chosen).**

## Consequences

- The dom and binding gates moved (+2.0 KB static). This is a renegotiation for a core capability, not an adapter: ADR 0001's "gates never move for an adapter" still holds. What the second half of it buys, gzip on dom: fallback flight ~0.25 KB, Chromium retry 0.19, idle prefetch + Save-Data 0.09, duotone filter 0.07, rest look 0.04 (+0.23 for winding evenodd elements and choosing the look by area), SSR paint 0.03, stale-load check 0.02; the Safari retry and a 128-point fallback guard +0.12.
- A fill icon must look right before the chunk, including in server markup. One `<path>` can't paint each element its own way, so it rests in the closest single look: stroke when stroke-only elements enclose more than 1.5× the filled area, fill + stroke if any element is stroked, else fill; always nonzero, with each evenodd element's subpaths wound by nesting so its holes stay holes; translucent duotone layers dropped. On 2,010 Iconify fill icons, 14 rest visibly off (IoU < 0.99 against the region) until the chunk lands, against 118 with one merged fill (0.7% on 6,693 held-out ones). The driver then upgrades the rest to the exact region; an icon mounted once the chunk is around rests on it at once.
- Network becomes part of the morph's first run. The policy:
  - A morph waits at most 100 ms for the chunk. Past that, or on a failed load, it flies a fallback that needs no chunk: the old shape shrinks into its centroid on the first half, the new one grows out of its own on the second. The load continues in the background, the resting icon upgrades to the exact region when the chunk lands, and the next morph flies. A load already older than the budget isn't waited for again.
  - A fill icon prefetches the chunk on idle at mount, never under Save-Data.
  - Superseded requests are dropped.
  - A failure does not trigger an immediate second request; the next morph that needs the chunk retries.
  - Chromium caches a failed dynamic import for the document's lifetime (verified on Chromium 152: a second `import()` of the URL fails without a request). The retry tries `import()` first (browsers that don't cache the failure fetch again), then re-runs the chunk as a `<script type="module">` under a fresh module-map key: the same URL plus a fragment, which reaches the server unchanged (CDN cache and signed URLs intact). The chunk registers its hooks on `Symbol.for("morphicons.region")`. This needs no bundler cooperation, where `import(url)` with a variable would (Metro rejects it outside node_modules). Chromium and Firefox name the URL in the error. Safari 26.2–27 caches the failure too but names no URL, so the URL is read off the loader's source (the bundler's chunk path) and resolved against the driver's own URL, taken from a stack frame (not `import.meta.url`: Metro doesn't parse it). It doesn't help where a CSP / Trusted Types policy blocks module scripts, or behind a failed `modulepreload` in Safari (its memory cache ignores fragments); `setRegionLoader(async () => region)` with a static import covers those. The spec now says failed fetches are not cached (whatwg/html#10327: Firefox 155, Chrome 156, Safari Technology Preview), so this step can go once those versions are the floor.
- Bundlers that don't code-split inline the chunk (Metro: the RN gate counts it).
- `setRegionLoader` / `preloadRegion` are the escape hatches: static import, CDN, prefetch on idle or hover.
- The winding is the picture under nonzero, so the planner keeps it right at every t, not only at the endpoints: a contour with holes is never duplicated (two copies wind +2 under a −1 hole and paint it), holes pair only with an overlapping hole of the paired outer and fly in that outer's frame, unmatched holes close on the first half of the flight and open on the second, and a vanishing piece takes its holes along one homothety; a vanishing hole moves with its outer's local blend, and a matched hole that strays mid-flight splits into one that closes and one that opens. `bench/region-topology.ts` checks every region pair of the vendored sets.
- Those rules were tuned on the vendored icons, so `bench/region-wide.ts` re-checks them on a seeded held-out sample of the full Iconify sets. There, 3.8–4.5% of random pairs paint > 1% outside the surface for a few frames (0.1–0.3% on the vendored icons), almost all outers folding over themselves; a check that takes the next correspondence offset when an outer's mid-flight blend crosses itself brought it down from 5.0–6.1%. What's left no offset avoids. That is the known limit of nonzero winding with one path and a correspondence uniform in arc length; the complete fix (holes as a mask, a non-uniform correspondence) costs DOM per icon and a `<mask>` in React Native, so it is deferred.
- A flight lands on its samples and then snaps to the exact region, so an icon whose contours 64 samples can't follow (a vertex more than 0.3 units off the 64-point polygon: spirals, snowflakes, cogs; ~10% of icons) samples at 128, and a pair mixing both doubles the 64 side with midpoints. The landing snap (IoU < 0.95) went from ~2% of icons to 0.2%; only those pairs pay, ~2× plan and frame cost.
- Bindings set `color` on the `<svg>` with `stroke`, so a filled path's `currentColor` is the prop. React Native has no cascade: its shim forwards paint through `setNativeProps`, republishes it on every render like `d`, and resolves `currentColor` / `inherit` to the prop.
