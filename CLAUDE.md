# morphicons

Universal morphing library for stroke-based icons (Lucide, Tabler, Heroicons, Iconoir; off-grid packs via `fitIcon`): any icon morphs into any other with spring physics and rotations that emerge from the math. **`README.md` is the source of truth** — it documents the API, the architecture and the full math pipeline with formulas.

## Status

The library is complete: `src/core/` (pure pipeline: parse → normalize F.6 → GL8 resampling with anchored corners and intrinsic sampling for closed paths → surjective matching with greedy guards → Procrustes with λ tie-break + circular correspondence + global hybrid → polar interpolation → serialization with Z → spring), `src/dom/` (`createMorph` with morphTo/set/**seek**/progress/destroy + singleton rAF scheduler + WeakMap caches + canonical snap + `reducedMotion` policy `"never" | "user" | "always"`, default never), `src/react/` (`MorphIcon` with 3 modes + exact SSR + a11y + lucide-react drop-in), `src/vue/` (`MorphIcon` for Vue 3: same 3 modes + exact SSR + a11y; plain render function with `h` — no SFC, no JSX, no Vue compiler), `src/svelte/` (`MorphIcon` for Svelte 5: same 3 modes + exact SSR + a11y; runes, thin `.svelte` shell over `shared.ts` — the component ships as SOURCE and the consumer's bundler compiles it via the `svelte` export condition), `src/react-native/` (`MorphIcon` over react-native-svg: same 3 modes + a11y; reuses the dom driver verbatim through a `setNativeProps({ d })` shim, reduced motion opt-in via `AccessibilityInfo` best-effort), `playground/` (multi-library demo, validated by eye).

- `bun test` → 206 tests / ~13,810 asserts. Performance: plan() 0.01–0.42 ms. Gzip size: core 6.60 / +dom 7.12 / +react 8.01 / +react-native 8.37 / +vue 8.04 / +svelte 7.66 TS half + 1.26 `.svelte` source (gates 7 / 7.5 / 8.5 / 9 / 8.5 / 8 / 1.4); adapters 4.03 aggregate = `{ svgToIcon }` 3.34 + `{ maskTarget }` 0.70 standalone (gates 4.4 / 3.7 / 0.8 — svgToIcon drags the lowering machinery standalone; shared-chunk incremental over core is ~0.4). maskTarget drives a hidden PAIR of **referenced** `<svg><mask><path>` buffers — each `d` write lands on the back buffer and flips `mask-image` (`url(#a)` ↔ `url(#b)`), because WebKit doesn't repaint on referenced-mask content mutation (frozen flight in Safari). NEVER a data-URI mask per frame (async decode in Chromium → blank flight) and NEVER inline-SVG injection into the host element (reverses the CSS-icon model's optimization) — docs/adr/0002, both found by eye in the testbench.
- Published on npm as **morphicons** (public, OIDC trusted publishing): bumping `version` in package.json on main IS the release trigger (publish.yml compares against the registry, publishes, tags, and then points `website/` at the new version — the site consumes the published package with an exact pin, weekly dependabot on `/website` as backstop). The bump commit carries the version's `CHANGELOG.md` entry (Keep a Changelog); publish.yml uses that section as the GitHub Release notes, falling back to autogenerated notes if missing.
- Not done (no date): golden screenshots in CI. The React Native binding shipped in 1.4.0; its by-eye validation runs in the external testbench (`~/Work/morphicons-testbench`, Expo app), not in this repo.

## Hard rules (non-negotiable)

- **Zero runtime dependencies**. None. devDeps yes; `react` (>= 18), `vue` (>= 3.3), `svelte` (>= 5) and `react-native` (>= 0.71) + `react-native-svg` (>= 14) are **optional** peers, only for `./react`, `./vue`, `./svelte` and `./react-native`.
- **The core never touches the DOM**: pure functions consume icon data and produce `d` strings and numbers. DOM only in `src/dom` (via ambient declares — compiles without `lib: DOM`); React only in `src/react`; Vue only in `src/vue`; Svelte only in `src/svelte`; react-native/react-native-svg only in `src/react-native`. The **root** tsconfig deliberately omits `lib: DOM` and excludes `src/{react,react-native,vue,svelte}` + `test/{react,react-native,vue,svelte}`; the playground/react/react-native/vue/svelte/build tsconfigs add DOM (and jsx where needed). `tsconfig.build.json` exists ONLY so tsdown can emit types — the separation is enforced by `bun run typecheck`.
- ESM only, TypeScript strict, `sideEffects: false`, subpath exports (`.`, `./dom`, `./adapters`, `./react`, `./react-native`, `./vue`, `./svelte`). The react-native entry needs Metro with package `exports` resolution (default since RN 0.79) — documented in the README, don't add CJS fallbacks for it.
- **Frozen core contracts + format adapters** (docs/adr/0001, glossary in CONTEXT.md). The core's input surface is `IconInput = IconNode | d string` and the driver's only write surface is `PathEl` — neither ever learns a foreign format. Every other representation (SVG markup in via `svgToIcon`, CSS-mask elements out via `maskTarget`, whatever comes next) lives in `morphicons/adapters`: one entry, each adapter an independent module so named imports tree-shake to just that adapter, pinned by **per-export size gates** (size-limit `"import": "{ svgToIcon }"`) — coupling two adapters trips CI, not a reviewer's eye. The aggregate adapters gate may grow as adapters land; core/dom/binding gates never move for an adapter. Adapters are per FORMAT, never per vendor — a `/iconify`-style branded entry is banned by design.
- The Svelte binding keeps `MorphIcon.svelte` **logic-free**: tsc never typechecks inside a `.svelte` (no svelte-check in the toolchain — it pins its own TS and may not coexist with tsgo), so every line that can be wrong lives in `src/svelte/shared.ts`, which IS typechecked. Bun compiles the component on the fly in tests via `bunfig.toml` `[test] preload` → `test/svelte/loader.ts` (`svelte/compiler`; server mode by default, client mode behind the `?client` import suffix — the loader anchors svelte imports to ONE physical copy because bun ignores the `browser` export condition).
- **The four bindings share ONE lifecycle contract** (README "Lifecycle contract"): lazy driver on iconless mounts (the first icon — prop or imperative — births it; `morphTo` without driver ≡ `set`), controlled wins over `icon` while `from`/`to` are both present, and every exit from controlled mode invalidates the frozen pair. No fix or behavior change may land in a single binding — the mount suites are mirrored on purpose.
- Size budget: **anti-regression tripwire, not a straitjacket** — gates carry ~10% headroom over what's measured. If a real capability needs more, the number is renegotiated; growing unnoticed is what's not accepted.
- Accepts `IconNode = [tag, attrs][]` (Lucide's data format) structurally typed — Lucide is **not** a dependency, not even a peer. `IconNodeAttrs` admits `undefined` on purpose (lucide's SVGProps includes it; the runtime treats it as an absent attr).
- The driver's `PathEl` is structural (`{ setAttribute }`): the dom driver tests use a fake element and a rAF injected into globalThis — the driver is never handed a real element there, which is what keeps `src/dom` honest about reading globals at runtime. Keep it that way. It is also what makes the react-native binding a shim instead of a port: the same `createMorph` writes through `Path.setNativeProps({ d })`. The BINDING suites are hybrid on purpose: logic with fakes where it is extracted (`test/svelte/controller.test.ts`) + real mounts on **happy-dom** for the framework wiring (`test/*/mount.*`); the react-native suites mount with real React on happy-dom while `react-native`/`react-native-svg` are replaced via `mock.module` (`test/react-native/mocks.tsx` — the Path mock honors the setNativeProps contract; test files load the binding with a dynamic import AFTER the mocks). happy-dom is a devDep preloaded for the whole run (`test/register-client-dom.ts` — vue captures `document` at import time); the deterministic rAF fake in `test/client-dom.ts` drives all client frames. No jsdom, no react-test-renderer (deprecated in React 19).

## Invariants (pinned by tests, never break)

From `test/invariants.test.ts`:

1. arrow-right → arrow-down: θ = 90°, σ = 1, res = 0 per subpath — **emergent** rotation group, no hand-declared groups.
2. plus → x: |θ| = 45°, res ≈ 0, σ ≈ 1.212.
3. menu → x: **minimal**-rotation folds (±45°, never 135°) — the orientation tie-break is `score = res + 0.05·|θ|/π`. This λ exists because shapes symmetric under inversion (lines) tie in residual; see README "Minimal-rotation tie-break".
4. Exactness at the endpoints: `interp(plan, 0) = A` and `interp(plan, 1) = B` with error < 1e-9.
5. Anchored corners: the original path's vertices are **exact** sample points after resampling (fidelity at rest).
6. Surjective matching: with p ≠ q subpaths, none appears or disappears — leftovers duplicate in place ("cell division"), never collapse to a point.
7. Interruptions: re-planning from the intermediate shape preserves spring velocity; never a NaN in any frame.

From `test/closed.test.ts`:

8. **Intrinsic** sampling of closed paths (anchors = corners only, not the M point): the same square with a different start point gives res ≈ 0 and θ ≈ 0.
9. square → diamond: |θ| = 45°, σ = √½ — emergent rotation in closed paths too, via circular correspondence (N offsets × 2 directions over the closed cloud).
10. Topology in flight: closed↔closed flies with `Z`; closed→open flies open (the loop opens at the optimal cut chosen by the circular search).
11. Block coherence (global hybrid): if the whole icon is congruent (global res < 5e-3), all subpaths share the SAME (θ, σ) — e.g. both arrow subpaths spin the same way — **and the block is rigid mid-flight** (block transport): centroids ride the shared similarity around the global centroid instead of lerping, so cross-subpath distances hold at t = 0.25/0.5/0.75, not only at the endpoints. Non-hybrid plans keep the plain centroid lerp (`block: null`).

From the driver and the bindings (`test/dom.test.ts`, `test/react/`, `test/react-native/`, `test/vue/`, `test/svelte/`):

12. Canonical snap at rest: input string **verbatim**; IconNode → `cubicsToPathD`. In flight, M/L polylines (+Z) with never a NaN.
13. Exact interruption: after a mid-flight `morphTo`, a frame with dt = 0 paints the **identical** intermediate shape (the snapshot is the plan's source).
14. `seek` is deterministic, does not start the scheduler, and a later `morphTo` takes off from the frozen shape. `progress =` equals seek on the active target.
15. Singleton scheduler: N flying instances share ONE rAF; when all settle, it stops (zero live timers).
16. SSR: `MorphIcon`'s initial `d` is computed once with the pure core and the framework never rewrites it; `label` → `role="img"` + `<title>` (react-native: `aria-label`, no `<title>` element in react-native-svg), no label → `aria-hidden`. Pinned for the four bindings — the Vue, Svelte and React Native suites mirror the React one (RN asserts on the mounted markup; there is no renderToString there).
17. Lifecycle contract, identical in the four bindings (mirrored `mount` suites on happy-dom + `controller` suite with fakes): **lazy driver** — an iconless mount paints `d=""` and the first icon to arrive (prop, pair or imperative) births the driver without animating, `morphTo` without driver ≡ `set`; **controlled wins** — `icon` changes are ignored while `from`/`to` are both present, dropping the pair hands the path back to `icon` (animated); **clean re-entry** — any exit from controlled mode invalidates the frozen pair, so returning to the same pair re-bases on `from` and equals a clean mount at that `progress`; unmount mid-flight destroys the driver and leaves zero live frames.
18. Reduced motion is an explicit policy, default off: `reducedMotion` = `"never"` (default) | `"user"` | `"always"` as a `createMorph` option + live `morph.reducedMotion` property and as a prop in the four bindings. With `"never"` morphs fly even with the OS setting on; `"always"` always jumps; `"user"` restores the pre-1.4.2 behavior (`morphTo` ≡ `set` while the setting is on, zero frames) — web via `matchMedia` inside the driver, react-native via module-level `AccessibilityInfo` state: ONE `isReduceMotionEnabled()` query + ONE `reduceMotionChanged` subscription for the whole process, armed lazily by the FIRST `"user"` instance (`"never"`/`"always"` never touch the bridge). The policy is live: when it changes together with the icon, the new policy governs that same morph (in Vue the mode watcher re-applies it itself — prop-watcher order is not creation order).

## Working method

A morph's quality is validated by eye, not just asserts. After every pipeline change: run the suite **and** open the playground (`bun run play`) to feel the key pairs (menu↔x, →↔↓, x↔check, plus↔x, circle↔square, square↔diamond, sun↔moon, settings↔aperture). If something looks off, describe it, encode it as a metric or tie-break (as happened with λ) and add the test that pins it. Intermediate states matter as much as the endpoints: the playground scrubber freezes exact t ≈ 0.25 / 0.5 / 0.75.
